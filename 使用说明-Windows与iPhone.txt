【iPhone A端 + B手机卡密查看网页：授权测试版】

重要：之前GitHub Pages上的GPS测试页只是读取本机坐标，不会上传到服务器，所以B端无法直接查看那次位置。
这套测试包提供三个网页和一个必须持续运行的后端：
  /a      = A端iPhone授权、开启共享与停止共享（需要HTTPS和前台页面）
  /       = B端手机输入卡密、查看最近位置、查看已上传的历史位置
  /admin  = 管理员设置卡密过期日期、生成卡密、撤销卡密

【部署方案（Windows亦可操作）】
1. 在GitHub创建一个新的源码仓库，不要将真实密码或设备密钥上传至仓库；上传本包的源文件及public文件夹。
2. 在支持Node.js服务、HTTPS和环境变量的云平台（例如Render Web Service）连接仓库；运行命令 node server.js 或 npm start。
3. 在平台环境变量中设置：
   ADMIN_PASSWORD：随机的管理员密码，至少16字符
   DEVICE_TOKEN：另一串不同的随机设备密钥，至少24字符
   PUBLIC_HTTPS：1
   PORT：通常不用手工设置，云平台会提供
4. 发布成功后，在浏览器打开 https://你实际获得的服务域名/api/health ，应显示 {"ok":true}。
5. 管理员访问 https://你的域名/admin，输入ADMIN_PASSWORD，自定义过期时间，点击生成新卡密并妥善保存。
6. A端iPhone访问 https://你的域名/a，输入DEVICE_TOKEN、勾选同意，点击“开始共享位置”，授权精确定位。
7. B手机访问 https://你的域名/，输入刚生成的查看卡密，看到A端最新上传位置、精度和时间。苹果地图按钮使用中国大陆WGS84→GCJ-02的转换参考坐标。
8. A端点击停止共享后，B端查看立即失效；刷新或切换到后台时，Safari页面不保证继续上传，后台测试需要原生iPhone APP。

【关于GitHub Pages】
GitHub Pages只能托管静态HTML，不能运行这里的Node.js API，不能单靠原来的GitHub Pages网址实现远程卡密查看。
旧定位测试页面可以继续保留，建议用新仓库部署此服务，避免覆盖原网页。

【注意】
- 本项目为概念验证，未经生产级安全审计。不要在公开仓库写入真实坐标、访问卡密或服务器密钥。
- 本地JSON文件保存历史，云平台若使用临时磁盘，重启可能丢失数据；正式使用须接入持久数据库、HTTPS、审计和更严格的访问控制。
- 测试版A端仅在明确开启共享、且Safari页面处于前台时采集；不会实现隐蔽后台追踪。
- 会话中显示的是“最后一次采集的位置”，不是保证实时的GPS位置；中国大陆地图坐标系由显示端适配。
- 这不是IPA，不能实现锁屏时每3分钟可靠采集。原生iOS APP要另行编译和签名。
